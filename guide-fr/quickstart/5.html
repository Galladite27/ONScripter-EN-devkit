ONScripter-EN - Guide de Démarrage Rapide Général: 5 - Choix pour le joueur

Now we will look at how to make choices for the player to take. Rather than being given instructions and examples, for this section we'll look at one worked example due to the larger amount of new concepts. Please do try to replicate and expand on this yourself for practice.

Labels & jumps

Before we add a choice, we need to look at labels. These are, as the name may suggest, names which refer to a certain point in the script. If you've had a look at the beginning part of the script in the template, you'll already have seen two. They are denoted by an asterisk followed by a simple word (allowing underscores), for example *my_label. The two already in the script are *define and *start.

These labels will serve as markers for the different outcomes of the choice - if the first option is picked, one label will be jumped to; if the second option, then another, and so on - and as you will see shortly, the goto command can also be used to jump to labels arbitrarily. Let us construct some sample dialogue with two routes, ready to add a choice to:

Code

; Ask a question

`Do you prefer apples or oranges?@


; Outcome if apples are chosen:

*apples

`Ooh, they're my favourite too!@


; Outcome if oranges are chosen:

*oranges

`Hmm, I prefer apples.@


; Story continues from both routes

`Either way, see you soon!\

Do you see the issue here? If "apples" is chosen, then after the line of dialogue for "apples" is printed, since the interpreter goes line-by-line unless interrupted, it will then pass over and print out the line of dialogue for "oranges" as well! We need to end each section with a jump, so we can force them to go to the same place after the choice-specific text. Let's add a label to converge to, and use the goto command to jump to it after the choices' text:

Code

; Ask a question

`Do you prefer apples or oranges?@


; Outcome if apples are chosen:

*apples

`Ooh, they're my favourite too!@

goto *after_apples_oranges


; Outcome if oranges are chosen:

*oranges

`Hmm, I prefer apples.@

goto *after_apples_oranges


; Story continues from both routes

*after_apples_oranges

`Either way, see you soon!\

Great! Now we're ready to add the choice selection!

Choices

The command we will use for choices is the select command. It works like goto, except that it gives the player a list of choices, and jumps to a label depending on the choice taken. It takes a variable number of arguments - it can take as many choice options as you like, but each one has to be followed by a corresponding label. Let us add this to the above code:

Code

; Ask a question

`Do you prefer apples or oranges?@

select "`Apples!",*apples,"`Oranges!",*oranges


; Outcome if apples are chosen:

*apples

`Ooh, they're my favourite too!@

goto *after_apples_oranges


; Outcome if oranges are chosen:

*oranges

`Hmm, I prefer apples.@

goto *after_apples_oranges


; Story continues from both routes

*after_apples_oranges

`Either way, see you soon!\

Althoug there are a fair number of symbols in the line, let's break it down and see how logical it is. Firstly, we have four arguments (string, label, string, label) each separated by commas. We can look at each element individually. The string is surrounded by speech marks, and has a backtick at the beginning, just after the opening quotation mark. This wasn't used in strings earlier, but was used in printed text - a simple rule of thumb is to begin lines of text with a backtick, and also begin strings which will/may be printed to the screen with a backtick. The filenames weren't, so we didn't need to worry there. The labels are as we covered above, denoted by an asterisk.
