ONScripter-EN full guide: 2 - sprites & backgrounds

This page will detail the usage of sprites and backgrounds, in the course of things also discussing aliases and effects. The reason for starting with this is so that we can produce visible effects with the syntax of normal (non-text) commands, leading afterwards into discussing things which produce no immediately visible effect such as labels and variables; and also because we will touch on aliases, effects and file types & access which are useful common topics to get out of the way. However, I do admit that this topic could just have easily been covered later on.

Image formats & transparency modes

ONScripter-EN supports three image formats: PNG, JPG, and BMP. The benefits and use cases of each are roughly the same (or, at least, the same as ordinary use cases such as small file size; that is, none of the formats particularly lend themselves towards any special use case in ONScripter-EN) except that BMP files can be compressed using NBZ compression in NSA archives, making them more practical than they otherwise might be with their potentially large file sizes.

Though an image format may support it (namely PNG), ONScripter-EN cannot interpret alpha channels. Instead, there are five "transparency modes" which can be used, three of which can be set as defaults using the define block only command transmode (with leftup being the default), in order to display images with transparency. The transparency modes are enabled on a per-image basis by adding a prefix to a file name when providing it to an image display function (for sprites or standing images). Please see the table below for an overview of these modes, as well as how they are set.

Mode Definition Default Per-image
Leftup The color of the top-left pixel will be used as the transparent color transmode l ":l;filename.bmp"
Rightup The color of the top-right pixel will be used as the transparent color ":r;filename.bmp"
Copy Shows the image as-is, no transparency settings transmode c ":c;filename.bmp"
Alphablend The right half of the image contains alpha-level data for the left half transmode a ":a;filename.bmp"
Mask Uses the given file as alpha-level data for the main image ":mfilename.bmp;filename.bmp"

The copy transparency mode does not apply transparency at all.

The leftup and rightup transparency modes rely on the intended transparent portions of the image being a solid colour which can be substituted for transparency. Ensure there is no feathering between the image and the colour, as only the exact colour is replaced. This method can lead to jagged edges.

The alphablend and mask transparency modes work in a similar manner. Both depend on there existing a second copy of the image (a mask) where black represents total opaqueness, white total transparency, and any shade in-between an intermediate level of transparency. For alphablend, the image is twice the ordinary width with the right half being the mask; with mask the mask is storerd in a separate file with its name provided.


Here is a method for taking an image and producing a silhouette for use with the alphablend transparency mode (using GIMP):

  1. Right-click the layer (assuming one layer with transparency) and select Add Alpha Channel
  2. Modify the image as required to translate its contents, using transparency as normal
  3. Go to the "channels" tab (next to layers by default) and hide all but alpha
  4. Go to Layer → New from Visible
  5. Reset (un-hide) the colour channels
  6. Go to Image → Canvas Size and resize it to be double the width
  7. Select the new layer containing the alpha channel data with the "alignment" tool (on the same spot as the "move" tool), select "Relative to Image," and click Distribute Right
  8. Add a layer at the bottom of the stack and right-click → remove the alpha channel to give it a white BG
  9. Export the image as BMP (bitmap) or PNG without alpha channel

Aliases

The syntax of aliases was already covered in page 1, which is most of what you need to know about their usage since it is quite simple. The define block only commands stralias and numalias are used to define aliases. Each takes two arguments, those being the alias name and the value for it to become associated with. After that point, any instance of the alias name in place of a string or number literal will be substituted with the alias's associated value.

Code


; Define a number alias

numalias my_alias,100


...


; In this command, "my_alias" will be substituted by the number 100

do_a_thing my_alias

In the context of filenames and particularly transparency modes, one of the use cases for this will become clear. Instead of giving a filename every time we want to reference an image (or otther file), we can define an alias once and then use that alias to reference the file. This can also let us easily use a non-default transparency mode for a certain file without specifying it each time. Both of these things reduce visual clutter, also making it easier to change every instance of a file name or its transparency mode at once.

Code


; Define a string alias

stralias sp_girl_happy,":a;sprites/girl/happy.png"


...


; Easily reference the filename with its transparency mode multiple times

ld l,sp_girl_happy

ld c,sp_girl_happy

ld r,sp_girl_happy

Effects and printing

Built in effects, the effect commands, effect masks, DLLs

Effects are referenced by effect number, which ranges from 0-255 - however, effects 0 and 1 are reserved and so user-definable effects range from 2-255.

In ONScripter-EN, many commands require an effect by which to write the changes they make to the screen. However, many others do not by default write their changes to the screen, and so the changes require explicitly writing to the screen to be made visible to the user using the print command (which accepts one argument, that being an effect number).

Effect 0 causes changes to be written to memory, but not to the screen; effect 1 causes changes to be written to the screen instantly, or in other words without effect.

So, since some commands require an effect number, they can be delayed in being made visible to the user by using effect 0 - the changes will then be made at the next usage of the print command; also, the command which accept no effect number can be displayed with effect by immediately being followed by a print command; so, in this way, any command's visible effects can be made to be either immediate or delayed. As for why some are immediate and some delayed by default, it seems that the rule is that the most commonly used method is the default (of course, there is also some plain inconsistency).

Code

; BG command requires an effect - draw immediately

bg black,1


; BG command requires an effect - delay drawing

bg black,0

...

print 1


; Monocro command doesn't require an effect - draw immediately

monocro #888888

print 1


; Monocro command doesn't require an effect - delay drawing

monocro #888888

...

print 1
