ONScripter-EN full guide: 2 - sprites & backgrounds

This page will detail the usage of sprites and backgrounds, in the course of things also discussing aliases and effects. The reason for starting with this is so that we can produce visible effects with the syntax of normal (non-text) commands, leading afterwards into discussing things which produce no immediately visible effect such as labels and variables; and also because we will touch on aliases, effects and file types & access which are useful common topics to get out of the way. However, I do admit that this topic could just have easily been covered later on.

Image formats & transparency modes

ONScripter-EN supports three image formats: PNG, JPG, and BMP. The benefits and use cases of each are roughly the same (or, at least, the same as ordinary use cases such as small file size; that is, none of the formats particularly lend themselves towards any special use case in ONScripter-EN) except that BMP files can be compressed using NBZ compression in NSA archives, making them more practical than they otherwise might be with their potentially large file sizes.

Though an image format may support it (namely PNG), ONScripter-EN cannot interpret alpha channels. Instead, there are five "transparency modes" which can be used, three of which can be set as defaults using the define block only command transmode (with leftup being the default), in order to display images with transparency. Alternatively, the transparency modes are enabled on a per-image basis by adding a prefix to a file name when providing it to an image display function (for sprites or standing images). Please see the table below for an overview of these modes, as well as how they are set.

Mode Definition Default Per-image
Leftup The color of the top-left pixel will be used as the transparent color (i.e. every pixel of the same colour as the top-left pixel is made transparent) transmode l ":l;filename.bmp"
Rightup The color of the top-right pixel will be used as the transparent color ":r;filename.bmp"
Copy Shows the image as-is, no transparency settings transmode c ":c;filename.bmp"
Alphablend The right half of the image contains alpha-level data for the left half transmode a ":a;filename.bmp"
Mask Uses the given file as alpha-level data for the main image ":mfilename.bmp;filename.bmp"

The copy transparency mode does not apply transparency at all.

The leftup and rightup transparency modes rely on the intended transparent portions of the image being a solid colour which can be substituted for transparency. Ensure there is no feathering between the image and the colour, as only the exact colour is replaced. This method can lead to jagged edges.

Warning

Ensure that you set a strong an otherwise unused colour (such as pure magenta) as the background when using leftup or rightup transparency modes, to ensure that no other parts of the image are accidentally made transparent (e.g. whites of eyes or bright spots on white clothing)

The alphablend and mask transparency modes work in a similar manner as one another. Both depend on there existing a second copy of the image (a mask) where black represents total opaqueness, white total transparency, and any shade in-between an intermediate level of transparency. For alphablend, the image is twice the ordinary width with the right half being the mask; with mask the mask is storerd in a separate file with its name provided.


Here is a method for taking an image and producing a silhouette for use with the alphablend transparency mode (using GIMP):

  1. Right-click the layer (assuming one layer with transparency) and select Add Alpha Channel
  2. Modify the image as required to translate its contents, using transparency as normal
  3. Go to the "channels" tab (next to layers by default) and hide all but alpha
  4. Go to Layer → New from Visible
  5. Reset (un-hide) the colour channels
  6. Go to Image → Canvas Size and resize it to be double the width
  7. Select the new layer containing the alpha channel data with the "alignment" tool (on the same spot as the "move" tool), select "Relative to Image," and click Distribute Right
  8. Add a layer at the bottom of the stack and right-click → remove the alpha channel to give it a white BG
  9. Export the image as BMP (bitmap) or PNG without alpha channel

Aliases

The syntax of aliases was already covered in page 1, which is most of what you need to know about their usage since it is quite simple. The define block only commands stralias and numalias are used to define aliases. Each takes two arguments, those being the alias name and the value for it to become associated with. After that point, any instance of the alias name in place of a string or number literal will be substituted with the alias's associated value.

Code


; Define a number alias

numalias my_alias,100


...


; In this command, "my_alias" will be substituted by the number 100

do_a_thing my_alias

In the context of filenames and particularly transparency modes, one of the use cases for this will become clear. Instead of giving a filename every time we want to reference an image (or otther file), we can define an alias once and then use that alias to reference the file. This can also let us easily use a non-default transparency mode for a certain file without specifying it each time. Both of these things reduce visual clutter, also making it easier to change every instance of a file name or its transparency mode at once.

Code


; Define a string alias

stralias sp_girl_happy,":a;sprites/girl/happy.png"


...


; Easily reference the filename with its transparency mode multiple times

ld l,sp_girl_happy

ld c,sp_girl_happy

ld r,sp_girl_happy

Effects and printing

Effects are referenced by effect number, which ranges from 0-255 - however, effects 0 and 1 are reserved and so user-definable effects range from 2-255.

In ONScripter-EN, many commands require an effect by which to write the changes they make to the screen. However, many others do not by default write their changes to the screen, and so the changes require explicitly writing to the screen to be made visible to the user using the print command (which accepts one argument, that being an effect number).

Effect 0 causes changes to be written to memory, but not to the screen; effect 1 causes changes to be written to the screen instantly, or in other words without effect.

So, since some commands require an effect number, they can be delayed in being made visible to the user by using effect 0 - the changes will then be made at the next usage of the print command; also, the command which accept no effect number can be displayed with effect by immediately being followed by a print command; so, in this way, any command's visible effects can be made to be either immediate or delayed. As for why some are immediate and some delayed by default, it seems that the rule is that the most commonly used method is the default (of course, there is also some plain inconsistency).

Code

; BG command requires an effect - draw immediately

bg black,1


; BG command requires an effect - delay drawing

bg black,0

...

print 1


; Monocro command doesn't require an effect - draw immediately

monocro #888888

print 1


; Monocro command doesn't require an effect - delay drawing

monocro #888888

...

print 1

Tip

If you're having trouble with commands seemingly not doing anything when they ought to be displaying to the screen, in addition to checking the API ref for usage notes make your first sanity check to be adding a print 1 after the offending line.

Defining effects

ONScripter-EN provides a variety of built-in effects. However, to use these, you must define an effect number based on one of these effects using the define block only command effect, which takes three arguments - the effect number to assign to, the built-in effect number, and the desired duration of the transition in milliseconds. The list of built-in effect numbers which can be used with this command (taken from the API reference) is as follows:

  1. Instantaneous display
  2. Left-sided shutter
  3. Right-sided shutter
  4. Upwards shutter
  5. Downwards shutter
  6. Left-moving curtain
  7. Right-moving curtain
  8. Upwards curtain
  9. Downwards curtain
  10. Pixelwise crossfade
  11. Left-moving scroll
  12. Right-moving scroll
  13. Upwards scroll
  14. Downwards scroll
  15. Fade via mask pattern
  16. Mosaic out (after using, screen state is uncertain like with effect 0)
  17. Mosaic in
  18. Crossfade via mask (processor intensive)

Please note that effects 14 and 18 require a fourth argument, a mask (as explained above) by which to transition, with white areas fading slowly and black areas fading quickly.

In addition, built-in effect 99 will be discussed below.

Code

; Sets effect 2 to be an upwards shutter of one second

effect 2,4,1000


; Sets effect 3 to be a two second masked fade

effect 3,15,2000,"m3.bmp"

Tip

The print command can be used with a built-in effect rather than an effect defined by the effect command, for example as a one-off. To do this, in place of the effect number use a built-in effect number with any other required arguments, such as print 4,1000 for the same one-second upwards shutter as defined above.

Effect DLLs

NScripter also supports effects provided by DLLs, which ONScripter-EN supports in a limited manner (due to its platform independence) through emulation.

Built-in effect 99 can be used with a fourth argument (like effects 14 and 18 above), with that argument being a string containing the DLL name, a slash, and any parameters to be passed to the DLL. In ONScripter-EN, four effects are supported (and no actual DLL file must exist, since they are internal to the engine) - breakup.dll, cascade.dll, trvswave.dll, and whirl.dll.

Code

; Sets effect 2 to be a whirl of one second

effect 2,99,1000,"whirl.dll"

Backgrounds

The bg command can be used to draw backgrounds. It takes two argument; for the first argument either "black" or "white," a colour (hex code), or filename, and then for the second argument an effect.

Code

; White background

bg white,1


; Red background

bg #FF0000,1


; Image background

bg "bg/street.png",1

A background can also be drawn over only a portion of the screen using the bgalia command.

Sprites

Like effects (and many other things in the engine), sprites are numbered independently, with sprite numbers ranging from 0-999 (and enhanced sprite numbers from 0-255). If you try to draw to an existing sprite number, the old sprite will simply be overwritten.

The lsp command is used to display sprites; it accepts a sprite number, image filename (or processing tag), top-left X co-ordinate, top-left Y co-ordinate, and optionally an opacity value (from 0-255). The image processing tags (which include, for example, transparency modes) are described very well and in good detail with examples in the API reference guide's section for the lsp command. Please do read that section; I will not unnecessarily repeat it here.

The csp command is used with a sprite number to clear that sprite; the vsp command is used with a sprite number and either a 0 or 1 to toggle the visibility of a sprite; the msp and amsp commands are used to modify sprites' position and opacity, relatively and absolutely respectively.

Enhanced sprites are like sprites, except that they can also have a rotation and X and Y scaling. They have their own set of commands similar to normal sprite commands but with a number 2 on the end, e.g. lsp2, msp2, &c., due to their different properties and independent indexing.

Animated sprites

One of the image processing tag features I will briefly touch on here is sprite animation. A sprite may be split into multiple "cells" (meaning, images placed side-by-side within a single image file) (with the alpha channel next to each cell respectively if required), and those cells animated either once or in a loop in one of several patterns. Using this, you can display GIFs of a reasonable size even though that format is not supported, by placing the frames side-by-side in a single image.

Tip

The cell command can be used to set an sprite to display a specific cell (indexed from 0). This could be used, for example, to store multiple poses or expressions for a character within a single sprite, rather than replacing the sprite to change which one is displayed:

Code

; Define aliases to make life easier

numalias cell_happy,0

numalias cell_sad,1

numalias cell_angry,2

stralias file_sp_boy,":l/3,0,3;sprites/boy.bmp"

numalias sp_boy,0


...


; Draw our sprite (will be cell 0, or in our case happy, by default)

lsp sp_boy,file_sp_boy,0,0

print 1


; Change to display the angry cell

cell sp_boy,cell_angry

print 1
