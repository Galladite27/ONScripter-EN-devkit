Extracting and repacking game archives

In order to extract image files for translation, and to replace the old images with their translated equivalents, it is very likely you will have to work with a game archive file using the provided archive file tools (see the "resources" section of this devkit).

Firstly, locate the game archive file(s). The main name you are looking for is arc.nsa, however any file ending in .nsa, .sar or .ns2 will do - just remember the original name.

To extract the archive, you will need to use the command line. First, ensure the appropriate tool (named after the file type + "dec") and the archive file are in the same directory (for example, nsadec.exe and arc.nsa). Then, open a terminal in that directory (on Windows, shift-right click on the directory and select "Open command window here"; on Linux, you should already know this). Finally, type the name of the tool, followed by -o out, followed by the name of the game archive file (for example, nsadec.exe -o out arc.nsa). This will extract all the resources from the archive into the new directory named "out."

To repack the archive, you will need the appropriate tool (this time, named after the file type + "make") in the same directory as before (so that the directory containing the extracted resources is next to the tool); also, make sure to remove the old game archive file. Then, open a terminal in that directory as before, and type the name of the tool, followed by the name of the original game archive file (before it was initially extracted), then by -d out (for example, nsamake.exe arc.nsa -d out). You should be left with a new game archive file with the same name as the old one. Put this back where the original one was and test your game.

Tip

If the file is of the .nsa filetype, you can enable compression of all .bmp and .wav files by adding the option -e before the -i option (for example, nsamake.exe arc.nsa -e -d out). This will take longer to create the game archive file, and may slightly impact performance in-game on older hardware, but will greatly reduce the size of the file.

Warning

Be careful about not touching the structure of the file hierarchy, and running these tools with the correct options and from the correct directories, otherwise it could cause the engine not to be able to find the rersources, even within the game archive.

Testing changes without repacking the script

It is unnecessary to rebuild the game archive directory every time you want to test changes made to its files. If you take all the contents of the directory containing the extracted resources and put them in the same directory as the engine, script, &c., then the engine will be able to read them as normal. If you do this, make sure you temporarily remove the old game archive file so that you know the engine is reading the extracted files and not the game archive file.

Locating and replacing images

While the resources are extracted, you can browse through the files to find images which need translating, edit them, and then replace the original with the new versions. Make sure you keep the resolution and other such factors the same, so that it integrates seamlessly into the place of the old asset.

Transparency and alpha masks

ONScripter-EN offers multiple methods for implementing transparency in images, and so we must treat this briefly so as to equip you to identify and prevent related issues.

It is possible that an image whose format supports alpha channels (such as PNG) has the transparency information baked into the image. Make sure to keep this consistent: if there is an alpha channel, keep it; if not, don't add one.

If you open an image for editing and notice the background is composed of a flat colour (often a bright one), the script is set up for this to be replaced by transparency. Either the top-left or top-right pixel of the image will be used to determine this colour; ensure you do not disturb this in your modifications.

If you open an image and see what appears to be a copy of the image to the right of the coloured image, but as a silhouette, the script is set up for the right half of the image to contain the transparency information for the left half. In this case, I have prepared a method outlined below for how to replicate this.

If you find that for each image, there is a corresponding silhouette of it but in a different file, the script is set up to use the silhouettes as masks for the colour images as before. If this is the case, follow the method I will now give for the previous case, but then split the image in half to create the colour and silhouette files.

Here is a method for taking an image with a silhouette and producing your own:

  1. Open the image, use Image -> Canvas Size to cut off the existing silhouette (if present)
  2. Right-click the layer and select Add Alpha Channel
  3. Modify the image as required to translate its contents, using transparency as normal
  4. Go to the "channels" tab (next to layers by default) and hide all but alpha
  5. Go to Layer -> New from Visible
  6. Reset (un-hide) the colour channels
  7. Go to Image -> Canvas Size and resize it to be double the width
  8. Select the new layer containing the alpha channel data with the "alignment" tool (on the same spot as the "move" tool), select "Relative to Image," put in an Offset X of the (half-width) image width, and click Distribute Left
  9. Add a layer at the bottom of the stack and right-click -> remove the alpha channel to give it a white BG
  10. Export as BMP (assuming this was the original format)
