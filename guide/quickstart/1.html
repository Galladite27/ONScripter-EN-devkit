ONScripter-EN general quick-start guide: 1 - displaying text

Open the script and scroll to near the bottom, where you see the line reading "`Game goes here.\." Portions of the above code may be mentioned as appropriate throughout this guide, however we will begin with the single most important element of a novel game - the dialogue.

Anything put here in the script (if you want, you can remove the single line of text already in the template and start fresh) will be interpreted as code for the game when the engine is run - everything above in the script is related to the setup of the engine and not the game itself. The engine reads lines one after another, continuing to the end of the script unless interrupted.

Finally before we begin, a couple more mandatory notes concerning the script: firstly, the script is broken into two main sections, those being the define block and the program block. The define block contains setup information, and the program block contains the content of the game. Secondly, any line beginning with a semicolon (;) is considered by the engine to be a "comment," and is therefore not a part of the program. These comments can contain anything, commonly notes from the scripter to himself. In the template script you will see comments annotating everything there already, and marking clearly the boundaries of the aforementioned define and program blocks.

Displaying text

Displaying text in ONScripter-EN is very simple. To mark a line as being English (or otherwise non-Japanese) text, begin it with a backtick character (`) as seen in the line of text already in the template. Then, you may put whatever arbitrary text you want after it, and when the engine reaches that line of the script it will simply display that line of text on-screen. Large amounts of dialogue can therefore be written in the script almost verbatim.

Code

`This is a valid line of text in the NScript language.

`This line is as well!

Warning

Certain symbols, such as the percentage symbol, may have functional purposes even within lines of text. These functional purposes, as well as avoiding them, are discussed in the full guide, page 1, under the heading of "Text."

Clickwait characters

If you have already tried writing your own lines of text in the template (which you should be doing, by the way!), you may have noticed that the text is printed out but without pause at the end. This is because we need to tell the engine to pause at the end of a line!

ONScripter-EN has two "clickwait characters," @ and \, which when used at the end of (or even in the middle of) a line of text will cause the engine to pause when it reaches it, waiting for the user to click before it continues. The difference? An at symbol causes a linewait, whereas a backslash causes a pagewait; the former will cause subsequent lines to appear on the same page, while the latter will cause subsequent lines to appear on a new page, erasing the old one.

Code

`This is on the first page.@

`As is this.@

`And also this.\

`This line is on the second page.@

`As is this.\

Try it out!

Tip

You may also notice that the animated icon indicating that the line of text is completed and the user may click changes depending on whether the engine has reached a linewait or pagewait. These icons are stored in the "assets" directory, and the engine is told to use them in the script.
